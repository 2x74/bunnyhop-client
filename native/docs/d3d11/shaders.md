# GLSL to D3D11 shader pipeline

**GO for machine translation and SM5 compilation.** All 105 GLSL program pairs (210 stages), including every
reachable player permutation, compiled to DXBC with verified layouts and matching stage signatures.
OpenGL remains the default renderer; D3D11 image and performance qualification is still required.

## Run it

From the repository root, with Python 3, Bun 1.4.3, CMake, Ninja and a C++20 compiler installed:

```sh
cd native && bun install --frozen-lockfile && cd ..
python3 native/apps/native/tools/d3d-shaders/run.py --translate-only
```

On Windows, run the following in an x64 Visual Studio developer shell using Windows SDK 10.0.22621.0:

```powershell
python native/apps/native/tools/d3d-shaders/run.py
```

Windows compiles both stages of every distinct pair to `vs_5_0` / `ps_5_0` DXBC with the SDK's
`d3dcompiler_47.dll`. Other hosts perform translation and interface checks only. `--jobs 4` is the default.
The tool builds its translators from the immutable revisions in
[`toolchain.json`](../../apps/native/tools/d3d-shaders/toolchain.json); Homebrew versions are not used.
C++ source extraction needs no SDL, GL context, application build or verifier WASM.

Output is under `native/target/d3d-shaders/output`:

- `manifest.json`: each creation site, reachable cache entry and identical-source alias.
- `<program>.json`: reflection for **every** cache entry, including aliases.
- `programs/<program>/`: extracted GLSL, linked SPIR-V, HLSL, Windows DXBC, reflection and compiler diagnostics.
- `report.json`: exact tool pins, source commit, flags, per-stage source hashes, timings, sizes and failures.

A program compile or reflection failure leaves a report and returns nonzero. Setup failures stop immediately. The separate
[`d3d11-shaders.yml`](../../../.github/workflows/d3d11-shaders.yml) workflow runs on pushes to
`ci/d3d11-shaders` on `windows-2022`, tests the pipeline and uploads these outputs even on failure.
`native-release.yml` is unchanged.

## Inventory

There are 19 GLSL `link_program` call sites: 18 fixed programs and one lazy player factory, covering 22 material/pass families.
`sun_shadows.hpp` and `water_*.hpp` use the world/depth programs rather than compiling additional shaders.
The extractor checks all native C++ source files and fails if a GLSL creation site is added or removed.
It evaluates the actual C++ shader declarations, concatenations, shader factory functions and
`player_defines()` in a small generated C++ executable. No translated HLSL is hand maintained.

There is also one existing HLSL blit program in `low_latency_windows.cpp`, already used by the DXGI
presenter at SM4. The tool extracts its unchanged source and separately compiles both entries at SM5;
`existingHlsl` records that result. Its reflection is under `programs/existing-dxgi-blit/reflection.json`.
It has no GLSL source to translate.

The five player assets are regenerated by `export-player-materials.ts` on every invocation, using the same
website sources and dependency lockfile as the native asset build. They total 187,558 bytes at the qualified
source revision. `FINISH_STYLE` and `FINISH_CODE` supply the reachable finish codes: **0 through 27**.
Runtime uniform values (cosmetic tier, player look, glow, fabric, environment switches and time) create no
additional compile permutations. The native factory never sets the website's `FINISH_LOD`.

## Translation and binding contract

The pinned glslang invocation is:

```text
-V -R --auto-map-bindings --auto-map-locations --set-default-uniform-block NativeUniforms 0 0 -l input.vert input.frag
```

`-R` **was tested** with these GLSL 330 default-block uniforms and accepts them. Linking also merges the
uniform declarations into a shared named block. The pipeline checks SPIR-V interfaces and compiled DXBC signatures before emitting success.

**Do not use glslang's automatic varying locations directly.** Even with `-l`, the player vertex and fragment
stages receive different locations for the same varying. The tool assigns matching locations by GLSL name in
both SPIR-V modules, then reflects again and verifies names, types and locations. It changes only `Location`
decorations for user varyings; vertex attribute locations and fragment output locations stay intact. New
array/matrix varying types fail explicitly until their location spans are implemented.

The ghost pixel shader reads only a subset of the vertex outputs. Matching semantic names alone still lets
FXC pack the two signatures differently. The tool retains the complete vertex-output declaration order in
each generated pixel-input struct, using the pixel shader's own names for consumed fields. Unread fields
carry no shader arithmetic. It then compares compiled DXBC semantic names/indices, registers, component
masks and types for every input supplied by the vertex shader.

SPIRV-Cross flags are:

```text
--hlsl --shader-model 50 --fixup-clipspace --flip-vert-y
```

Windows uses `D3DCOMPILE_ENABLE_STRICTNESS | D3DCOMPILE_IEEE_STRICTNESS |
D3DCOMPILE_OPTIMIZATION_LEVEL3` (FXC `/Ges /Gis /O3`), with validation enabled. The SDK version and compiler DLL SHA-256 are both enforced. Compiler time measures
`D3DCompile` itself, excluding process startup and reflection. DXBC includes reflection data.

Reflection preserves the original uniform name, storage type, byte offset, byte size, array dimensions,
array/matrix strides and nested SPIR-V type definitions. `hlslName` connects generated names such as
`_13_viewProjection` back to `viewProjection`. On Windows, `dxbc` additionally contains authoritative
`D3DReflect` buffer layouts, resource slots and signatures. Every reflected DXBC variable is checked against
its original-name offset and available storage size. Cbuffer sizes are rounded up to 16 bytes.

The backend should construct per-program, per-stage name tables from these files. A name can occur in both
stages. Treat an absent/optimized-out resource like GL location `-1`. Bind each texture and sampler to its
reflected **stage-local** slot; GLSL texture-unit integers are not HLSL registers. One GL unit may fan out to
several pairs: the native player binds `uFinEnv`, `uCosEnv` and `uPlayerEnv` to unit 9, so D3D must bind that
same cube and sampler to every reflected pair. `spirv.textures` describes declared bindings, while
`dxbc.resources` identifies bindings surviving optimization.

Vertex inputs use `TEXCOORD<GL attribute location>`, with the name, GLSL type and location in `vertexInputs`.
Build the D3D input layout against the actual DXBC input signature and native vertex stride/offsets; do not
reinterpret all attributes as float4. Vertex/instance IDs use system-value semantics and require no buffer field. Aura shells use `gl_InstanceID`;
keep the current zero-based instance draws (no nonzero base-instance emulation is enabled).

## Semantic requirements for the backend

| Risk | Observed translation and required behavior |
| --- | --- |
| Clip depth | `--fixup-clipspace` emits `z = (z + w) * 0.5` at the vertex exit. Keep existing GL projection matrices and depth reconstruction; changing matrices too would apply the conversion twice. The world shader's manual shadow-matrix `*.5+.5` stays correct with GL matrices. |
| Render-target Y | `--flip-vert-y` negates final vertex Y. Keep all intermediate D3D targets in GL's numeric row convention: row zero corresponds to GL's bottom row. Texture UVs, framebuffer copies and integer texel fetches then retain their numeric coordinates. Present to the top-left swapchain with **one final vertical flip** (the existing DXGI blit already does this). Direct draws to the swapchain need the same policy. |
| Fragment coordinates | SPIRV-Cross maps XY directly from `SV_Position`; it does not insert `height-y`. With the chosen vertex flip, target row numbers match GL fragment Y. This preserves water screen UVs, contact-noise coordinates and ghost Bayer coordinates in intermediate targets. A backend choosing conventional top-left targets must instead convert fragment Y, target-texture UVs, derivatives and readbacks together. |
| Derivatives | The row convention above preserves the numeric Y axis for `dFdy`, normal reconstruction and procedural finish gradients. Flipping only sampled UVs would leave derivative signs inconsistent. |
| W and depth | Current shaders read fragment XY and world fragment Z, never fragment W. SPIRV-Cross inserts a reciprocal-W adjustment; it is unused here. Depth textures still contain 0..1 values after the vertex fixup, as GL depth textures do. |
| Clip distance | World and depth vertices emit `SV_ClipDistance0`. D3D11 has no GL enable bit for a declared clip distance. Supply the existing `no_clip_height = -1e30` outside planar reflection; use the actual water plane only for reflection. |
| Facing | Preserve GL's CCW/CW switches for planar reflections and mirrored viewmodels using corresponding D3D rasterizer states. The vertex Y flip changes winding; verify `SV_IsFrontFace` with culling and the water shader's two-sided branch. |
| Texture operations | Real `textureLod` becomes `SampleLevel`, `texelFetch` becomes `Load`, `textureGrad` becomes `SampleGrad`, and shadow sampling becomes `SampleCmp`. Preserve mip clamps, filtering, comparison function, border color and addressing modes. No compiled native source currently calls `textureSize`. |
| Bone matrices | `boneMatrices` is **sampler2D**, not a matrix uniform array. Preserve the three RGBA32F texels per bone and integer `Load(int3(x, bone, 0))` addressing. It needs an SRV; FXC can eliminate the unused sampler state. |
| Cubes | `samplerCube` becomes `TextureCube` plus sampler state. The current native environment is a black 1×1 cube on all six faces, so face orientation has no observable effect today. Nonconstant future cubes need an explicit face/orientation test. |
| Uniform packing | GLSL bools become 32-bit uints in the block: upload 0/1, never C++ bool bytes. `vec3` arrays use 16-byte strides (`uPalette[8]` is 128 bytes; `uGlove[5]` is 80). Water arrays likewise require strided writes. Matrices use generated `row_major` declarations with reversed `mul` operands, preserving existing column-major GL upload bytes. |
| Structs | The real player `Garment` struct is local shader math, not a uniform struct. DXBC compilation exercises it. There are no uniform struct instances in the current set; nested type metadata is retained for future layouts. |
| Loops | Water's plane loops, blur's uniform radius, fixed occlusion/shaft loops and all procedural finish loops must pass the real `/O3` compiler. The FXAA bound rewrite below is required; no sampling operation or optimization/validation flag is changed. |
| Precision and NaNs | HLSL uses 32-bit float and `/Gis`; no half precision or fast-math substitution is requested. GPU transcendental approximations, denormals, NaNs, zero normalization, implicit-derivative behavior and procedural `sin` hashes can still differ from GL. Compile success cannot establish pixel identity. |

FXC diagnostics are retained in `compile.log`. The compile run emits X3571 (`pow` with a possibly negative
base), X4000 (possibly uninitialized function results), and X3570 (gradient-driven loop unrolling). The
reported `fxPonyMapped`, `cosReflect`, `polishedShade`, `skyTexture` and `faceColor` functions have explicit
returns on all source paths; no missing initialization was found in that audit. These warnings are not
suppressed. Near-zero normalization, out-of-domain powers and divergent implicit derivatives remain visual
comparison targets rather than reasons to change the website's shader math speculatively.

The orientation contract is a backend integration requirement, not a rendered-image result. Compare water
reflection/refraction, shadow edges, ghost dithering, mirrored guns and procedural finishes on actual hardware
before enabling D3D11 by default. The only runtime GLSL edit is the FXAA loop below.

## Compatible GLSL change

`enhanced_look.hpp` changes only the FXAA search header:

```glsl
// Before
for(int i=0;i<10&&!(done1&&done2);i++){
// After
for(int i=0;i<10;i++){if(done1&&done2)break;
```

The original became an unbounded-looking HLSL `for (;;)` after SPIR-V short-circuit lowering. FXC failed
with X3511 after attempting 702 unrolled iterations. The new source gives FXC an explicit ten-iteration
bound. For every input, both forms execute the same sampling/arithmetic statements in the same order and
exit before the same iteration; there are no side effects in either condition. OpenGL's defined pixel
results are therefore unchanged by control-flow equivalence. No other runtime shader source, generated
website asset or OpenGL code is edited. Rendered-image comparisons were not run.
