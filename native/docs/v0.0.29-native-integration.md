## Input integration contract

Paths below are relative to `native/apps/native/`.

1. Startup checks original ABI 1 plus `bh_v29_check_abi(1, sizeof(BhRecordOptionsV29), sizeof(BhTimingSegmentV2))`. New layouts are 20/72 bytes; unknown layouts fail. Existing structs stay unchanged.
2. After `bh_record_begin`, set version 1, struct size, frozen float32 yaw/multiplier rates and timed-input flag 0. Clamp rates to 60–720 degrees/s and 1–4 (defaults 210/2). Mark the sticky timed flag only when the scheduler contributes.
3. Fast=`1<<6`, left=`1<<7`, right=`1<<8`. Turn only with exactly one direction. Compute `direction * double(yaw_speed) * (fast ? double(angle_speed_key) : 1) * dt` left to right, once per command. Wrap the double base with positive modulo; preserve counts/sensitivity. Rebase kind 6 means turn; combine existing provenance with `0x80`. Custom rates no longer imply raw provenance. Update the native Legit Scroll mask to forbid all three bits when the turn branch lands.
4. BHTS stays after other trailers and before gzip. For 300/2.5: `42 48 54 53 00 00 96 43 00 00 20 40`. Absent means legacy 210, no fast bit. Keep integer v8/v9 and fractional v10 formats; use `bh_step_look_v2`.
5. Enable timing observation before stepping. Query path version 2, preallocate storage outside the tick loop, then reuse it. Unsupported/absent paths need the shared chord fallback; discrete segments test only their destination. Final ms scoring awaits the upstream policy.
6. For practice, load/seek on the live context, check the current map zones, then call `bh_practice_from_replay(ctx, selected_style)`. Resync view from the last command (spawn angles at tick zero), clear pending input, set `prev=curr`, reset the clock, stop heartbeats and keep practice sticky until restart. Reject gauntlets. Takeover failure preserves playback.

Only startup ABI checks were added to `src/client.cpp` and `src/runner.cpp`. The event pump, tick scheduling, key handling, limiter and menu implementation were left for their owning branches.

## Hena's 43-second replay of a 24-second run

The reported difference is consistent with roughly 19 seconds of spawn prelude. The original replay was not supplied.

`src/client.cpp::reset` calls `begin_record` immediately after reset. `native-bridge/src/recording.rs::begin_record` requires tick zero, and `record_tick` retains every subsequent command. `finish_record` stores timer start/end ticks but keeps the prelude. `open_replay` starts at tick zero and the native timeline uses `totalTicks`.

The pinned web `session.ts::onReset` clears its recorder; `afterStep` also pushes before the timer starts. It does not trim the BHR. Web video export already uses `viewer/export-options.ts::clipRange` to trim the visible range.

Keep the verified BHR unchanged. In the native replay open/export paths, use a separate playback range: start at `max(0, startTick - round(1 / tickInterval))`, end at `min(totalTicks, endTick + round(1.5 / tickInterval))`, and retain a full-recording option. Seek by re-simulation through the prelude, then show range-relative time and constrain playback to that range. Ghost timing stays anchored to `startTick`. This removes the idle wait without changing moving entities, checkpoints or heartbeat indices.

Changing recording start itself also changes reset and pending-input baselines, so it belongs with `native/input-timing`. Slicing command arrays or resetting at the timer's start is not a valid replay trim.

`3cd68ab1a59fb71b32f448a1be195f9ceaf3074ccb5ccb89b72ed2014f563242`

Build it without touching the upstream checkout:

```sh
rustup target add wasm32-unknown-unknown --toolchain 1.99.1
bun tools/build-upstream-wasm.ts --upstream /path/to/bunnyhop
bun apps/native/ensure-wasm.ts
```

The tool uses upstream's build script and Cargo.lock, remaps its temporary source path, checks the digest, and caches bytes under target/. Repeated builds in different directories produced the same hash. `ensure-wasm.ts` rejects a source-commit or rules mismatch.
