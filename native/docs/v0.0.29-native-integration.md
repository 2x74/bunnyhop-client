# Web v0.0.29 integration

Synced commit: `042dca417ae08ab7cf3fd37591eae21ef772aab1` (`release-0.0.29`, including ms timing and ranking).
Physics remains 18; timer rules remain 2. See [upstream deltas](upstream-deltas.md).
`crates/native-bridge` is native-owned; vendored core and web changes use the sync tool.

## Wired in C++

- Startup checks ABI 1 and the v29 version and 20/72-byte layouts.
- The production scheduler uses integer nanoseconds. Timed input contributes at each
  tick's cutoff; capped gaps fold old input into the first retained cutoff, including
  holdback and accumulator remainder. Queues compact consumed entries and fold long
  stall backlogs while preserving counts, ordered pitch and final key state.
- Recording options freeze float32 yaw speed and fast-turn multiplier before stepping.
  Defaults are 210 degrees/s and 2; valid ranges are 60–720 and 1–4. Fast turn is bit 6
  and applies with exactly one turn direction. Kind 6 rebases preserve other provenance
  with `0x80`. Legit Scroll strips all three turn bits outside local practice.
- Timestamped reports or key edges mark the recording's sticky timed-input flag.
  BHTS remains the final trailer before gzip. For 300/2.5 its bytes are
  `42 48 54 53 00 00 96 43 00 00 20 40`. Legacy and fractional counted looks remain supported.
- Replay practice seeks by re-simulation on the live context, checks current map zones
  and selected style, and calls `bh_practice_from_replay`. View and pending input reset;
  world/timer/filter state continues. Practice stays active until restart and stops
  ranked heartbeats and recording export. Gauntlets and multiplayer reject takeover.
- Replay opening and video export default to `[startTick - round(1 / tickInterval),
  endTick + round(1.5 / tickInterval)]`, clamped to the recording. Seeking re-simulates
  the prelude. Native controls show range-relative time and stop at the range end.
  Full-recording mode restores the entire timeline. BHR downloads retain the verified
  bytes; ghost timing stays anchored to `startTick`.

## Menu message contracts

The menu sends and reads these messages:

- Settings: `{type:"settings", patch:{yawSpeed:300, angleSpeedKey:2.5}}`.
  These are `cl_yawspeed` and `cl_anglespeedkey`; changes apply to the next recording.
  Bind fast turn with `patch.binds.turnFast`, for example `["ShiftLeft"]`.
  Stop sending `yawSpeedAlt`; old saved files migrate that absolute speed to a multiplier.
- Practice: open a replay, then send `{type:"practiceFromReplay"}` to continue at the
  current tick, or add `tick` as an absolute recording tick. Select the matching main
  style first; bonuses use Normal. Failure leaves the viewer active and reports a host error.
- Viewer toggle: `{type:"replayControl", action:"fullRecording", value:true}`.
  `false` restores the default range. Initial `replay`/`replayData` play messages also
  accept optional `fullRecording` (default false).
- Host `playback.tick` and `totalTicks` stay absolute. Use `rangeStartTick`, `rangeEndTick`,
  `rangeTick`, `rangeTotalTicks` and `elapsedSeconds` for the displayed timeline;
  `fullRecording` reports the toggle. Seek messages still carry absolute ticks within the range.
- Video: existing `{type:"videoExport", action:"start", options:{...}}` accepts
  `options.fullRecording` (default false). Omit `from`/`to` to export the default range,
  or set the flag to export the whole recording. Explicit clip bounds are absolute and
  must fit that selected range. An old `from:0,to:totalTicks` request uses the default trim.

## Remaining work

The vendored core and the canonical WASM are unchanged from `9cde9db9`: upstream's ms timing is TypeScript only.
Native still scores whole ticks. Fractional-millisecond scoring needs:

- the bridge timer to follow `run-timing.ts`: an exit phase for a walk-out start and an entry phase for the finish,
  from the step's accepted path (`bh_timing_path_v2`, already exported) or a straight hull trace, quantised to
  millionths of a tick and rounded once to whole milliseconds (timing policy 1);
- the C++ HUD, end card, local PBs and replay library to show and compare that millisecond time;
- run submission and the replay viewer to report `timeMs` (the server recomputes it from the replay either way);
- `record-proof.ts` to compare the native millisecond score again; until then it compares the tick clock and
  reports `nativeTickSeconds` beside the verifier's `webTimeMs`.

Other upstream v0.0.29 changes the C++ client does not follow yet:

- bhop_shutdown restarts give the start zone's `asdf` targetname (`restart.ts`), as bhop_japan's classname does;
- a practice spawn saved after noclip or a checkpoint teleport keeps restarts practice (`start-point.ts`);
- the web timeline hides a long spawn wait; native already trims the default range to one second before the start.

The web settings panel bundles inside the native menu boundary (`settings-panel-boundary.test.ts`). The leaf
modules from upstream `v29/native-leaf-modules` are not merged into `release-0.0.29`, so `input-bits.ts` and
`crosshair.ts` stand in for them; drop both adapters once upstream has `input-bits.ts` and `hud/crosshair.ts`.

The pinned web style oracle predates fast-turn bit filtering; its Legit Scroll comparison
accounts for bit 6 explicitly, while a separate v29 test requires all turn bits to be cleared.

Scripted-clock parity matches all 39 scenarios / 1,819 ticks. Native tests cover the
real startup sequence, replay Tab routing, stall/backlog bounds, zero queue allocations
at 8 kHz, timed/BHTS header roundtrips, practice takeover and replay/export ranges.
Physical mouse acceptance and Windows/Linux desktop behavior require target-OS testing.
