# Native simulation, assets, practice, and replay bridge

The ABI is declared in `apps/native/include/bunnyhop_native.h`. `BhState` retains its original layout. The additive `BhSnapshot` exposes stamina, base velocity, player extras, weapons, and movement mode; `bh_snapshot_bytes` returns the existing core's canonical diagnostic bytes, not a restorable save-game format. Entity and model JSON support the existing zone/restart preparation outside the live simulation.

`run.rs` ports `apps/web/src/timer.ts` and the AABB rules in `zones.ts`. Timer calculations use f64, with f32 velocity writes for prespeed clamps. Once configured, `bh_step` owns prehop blocking, movement, timer updates, and the post-step prespeed clamp. Callers must not repeat these operations in JavaScript or apply external velocity mutations to a recording.

A recording follows this order:

1. Load the BSP/content, set settings and client build identity, and configure authoritative zones/options.
2. Reset; optionally apply the settled restart position/yaw and approved restart names.
3. At tick zero call `bh_record_begin`. A null/empty path retains only bounded native commands/checkpoints; a supplied path also creates diagnostic JSONL evidence.
4. Call `bh_step` with canonical input commands, before style filtering. `bh_run_state` supplies native timing, stats, and update flags.
5. On the finish tick, end recording and call `bh_record_write_bhr` with a new output path. The gzip BHR is encoded from frozen native memory, including the actual restart point and captured identity/settings/zones.

`bh_style_set` supports all eight shared styles: Normal, Legit Scroll, EZ Scroll, W Only, Sideways, Half Sideways, Low Gravity, and Auto Strafe. It applies canonical style settings and resets the loaded game and timer; configure the restart position and begin recording afterwards. `bh_step` applies the exact shared style/auto-strafe transform itself, including ladder exemptions and historic physics behavior. `bh_last_command` returns the filtered command actually simulated and recorded; callers must not filter it again. Movement must fit i16 during recording. Settings, reset, zone, position, external velocity, name, and identity changes invalidate an active recording. The 180,000-command limit closes the recording invalid; existing files are never overwritten. A finished recording stays independent of subsequent game movement.

`bh_record_fold` folds exact retained commands over `[from_index,to_index)` using shared `run-hash.ts` semantics. Command index zero produces state tick one. Run-clock folding starts at `timer.startTick`, exactly as in the web client; `BhRunState.rolling_hash` instead covers the whole recording from index zero. `bh_step_look` accepts real whole mouse counts, base/sensitivity/epoch rebases, and frame/event/report telemetry. Exactly representable samples use the existing counted v8/v9 format; absent or inconsistent samples fall back to the existing uncounted format. No input evidence is fabricated. `bh_record_cosmetic`, `bh_record_inspect`, and `bh_record_loadout` write the existing optional presentation trailers; these do not affect simulation or verification.

Optional JSONL evidence has one `header`, one `tick` row per command, and a final `summary`. Each tick includes the command's yaw/pitch bits, post-clamp state, timer, checkpoint marker, and command hash. State `floatBits` ordering is position xyz, velocity xyz, view offset z, teleport angles, angle change, touch position, stamina ms, base velocity xyz, health, gravity scale, speed scale. These retain NaN/signed-zero bits even when their numeric JSON presentation cannot. `valid` concerns capture integrity; files remain unverified until the authoritative server verifies them.

`bh_replay_header` supplies bounded replay-library metadata without loading/changing a map. `bh_replay_load` decodes raw or gzip BHR versions 1–10 and checks the loaded BSP digest. `bh_replay_step` feeds its already canonical commands directly into the same native Game/timer; `bh_replay_seek` resets and deterministically resimulates to the requested state tick, checking position/velocity checkpoints. Seek currently costs O(tick); callers can use a separate context for replay viewing. `bh_replay_stop` leaves replay mode, and a normal reset/style selection also exits it. Optional malformed cosmetic trailers are ignored as in the shared reader. Replay info retains packed loadout metadata; `bh_replay_events` exposes swings and inspect state over `(from,to]`.

`bh_ghost_load` builds immutable per-tick frames in an independent Game, preserving the whole live Game, timer, style filter, command, and finished recording. Load ghosts before beginning live recording. Up to four ghosts are retained per map; `bh_ghost_free` releases one. Decoding is bounded to 32 MiB compressed, 128 MiB raw, and two million commands; ghost precomputation is bounded to one million commands. Ghost loading is synchronous. Ghost frame queries are read-only and need no hidden JavaScript simulation.

Renderer data uses the existing Rust Source loaders: world/sky geometry and blend weights, six sky face materials, typed sky fog/camera data, per-material extras and names, static/entity props with shared material/texture indices, water volumes/planes, weapon/attack/floor reports, and lazy Source studio model/animation handles. `bh_content_read`/`bh_texture_path` resolve requested loose-root dependencies safely with BSP pak precedence. Renderer queries do not change authoritative simulation. Trigger/clip overlays expose the core's actual volumes and current entity flags. `bh_surface_at` ports the shared world-mesh audio grid, returning surface class, material index, floor height, and overhead water height.

Practice checkpoints retain full GameState, native timer/style/settings, and view angles, bounded to 100 checkpoints/128 MiB. Restoring a checkpoint or using practice noclip invalidates an active recording. `bh_noclip_move` ports the shared practice flight in double precision; `bh_practice_noclip_tick/exit` run the existing collision-free world tick and Source free-space search. `bh_trace_camera` queries current world/prop/brush collision for third-person cameras. Practice mutations never become ranked command streams.

Validation:

```sh
cargo test -p bunnyhop-native-bridge --locked
bun crates/native-bridge/tools/record-proof.ts --map /path/map.bsp --replay /path/finished-route.bhr --output /new/proof-directory
```

The proof derives the current physics version (15 for this integration) against the selected production WASM, compares every native state/timer/stat row, checks incremental native command hashing, compares the native BHR's decompressed bytes to the shared JS encoder, and runs shared `verifyReplay(..., ranked: true)`. A modified checkpoint must be rejected. It performs offline verification; it does not submit a score or bypass build/session admission. The proof also checks native replay playback, seek, and ghost state preservation. Tests cover all 120 style/physics combinations against 38,400 shared StyleFilter oracle rows; counted telemetry/rebases against the shared recorder; native practice flight against 1,800 shared noclip rows; checkpoint restoration; renderer query isolation; ABI layouts; malformed/truncated replays; optional presentation trailers; no-evidence captures; frozen output; mutation invalidation; SHA-256 vectors; and recording limits.
